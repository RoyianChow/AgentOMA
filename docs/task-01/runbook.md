# Task 01 local runbook

This runbook operates only the G1-approved synthetic sandbox. It must run on
loopback at `http://127.0.0.1:3101`. It never reads the root `.env`, production
credentials, patient data, production cookies, database, storage, or hosted
resources.

## Preconditions

- Use npm and Node 24 for the captured evidence runtime.
- Use a fresh terminal with no production/provider environment variables. The
  sandbox intentionally refuses if names such as `DATABASE_URL`,
  `BETTER_AUTH_SECRET`, `SUPABASE_*`, `OPENAI_*`, `HTTP_PROXY`, or `NO_PROXY`
  are present.
- Install the root lockfile, then install the sandbox workspace locally so
  Next and Turbopack share one framework module graph:

```powershell
npm ci --ignore-scripts
npm install --prefix apps/experiment-sandbox --no-workspaces --ignore-scripts
```

The second command creates ignored workspace dependency state only. Do not
commit an `apps/experiment-sandbox/package-lock.json` generated by that
standalone install.

## Required synthetic environment

Every build, start, lifecycle operation, and local dev process needs all seven
values below. Use a new short-lived instance ID and an expiry no more than 30
days after the build timestamp. The G1 decision ID is fixed.

```powershell
$built = (Get-Date).ToUniversalTime()
$env:SANDBOX_MODE = "synthetic"
$env:SANDBOX_BUILT_AT = $built.ToString("o")
$env:SANDBOX_EXPIRES_AT = $built.AddDays(7).ToString("o")
$env:SANDBOX_INSTANCE_ID = "SYNTH-LOCAL-001"
$env:SANDBOX_ORIGIN = "http://127.0.0.1:3101"
$env:SANDBOX_G1_DECISION_ID = "G1-2026-07-31-task-01"
$env:SANDBOX_DISABLED = "false"
```

Do not copy production variables into this shell. A denial is evidence that
the boundary is working, not a reason to weaken the validator.

## Verification commands

Run the isolated gates from the repository root:

```powershell
npm run sandbox:verify
npm run sandbox:verify-artifact --workspace @agentoma/experiment-sandbox
npm run sandbox:verify-evidence --workspace @agentoma/experiment-sandbox
```

`sandbox:verify` runs strict TypeScript, sandbox lint, Vitest, and the import /
storage / production-source boundary scan. The checked-in evidence manifest is
intentionally `PENDING`; final CI evidence must bind red/green results to the
tested commit.

Build and run locally:

```powershell
npm run sandbox:build
npm run sandbox:dev
```

The wrapper appends `--webpack` to the sandbox production build because the
local egress preload must coexist with Next's build workers. The production
root build remains unchanged and continues to use its existing command.

## Lifecycle controls

With the required environment still set:

```powershell
npm run inspect --workspace @agentoma/experiment-sandbox
npm run disable --workspace @agentoma/experiment-sandbox
npm run inspect --workspace @agentoma/experiment-sandbox
npm run reset --workspace @agentoma/experiment-sandbox
npm run teardown --workspace @agentoma/experiment-sandbox
```

Disable creates only the exact instance sentinel. Reset removes that sentinel.
Teardown removes only the exact contained `SYNTH-*` directory and is
idempotent. No command accepts a wildcard or arbitrary path.

## Production-invariance proof

Run the production build separately, then compare its normalized output with
the approved baseline:

```powershell
npm run build
npm run verify-production --workspace @agentoma/experiment-sandbox
```

The verifier must report `PASS` for unchanged app-path count/hash, route names,
runtime NFT, required server files, production dependency entries, production
script entries, and no sandbox markers. It prints counts and hashes only.

## Promotion boundary

G1 does not grant G2 hosted preview or G3 production import. Do not add a
database, storage, provider, analytics, model, patient/pharmacist fixture,
production module, production credential, deployment file, tunnel, LAN bind,
or external destination. Any such need requires a revised design package and
new approval before code is written.
