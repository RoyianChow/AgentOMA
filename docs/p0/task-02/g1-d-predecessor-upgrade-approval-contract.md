# Task 02 predecessor-upgrade G1-D approval contract

This is an executable approval format, not an approval. The harness remains
inert until a product lead grants G1-D for one clean candidate and records a
JSON document matching this contract. The 2026-08-02 implementation approval
does **not** satisfy this gate.

The schema is exact and rejects additional fields, broader authority, expired
windows, a dirty or different candidate, changed migration bytes, changed
migration ordering, missing actions, or different Docker resources. Approval
values are never printed. The approval artifact's SHA-256 is recorded in the
run evidence.

The image must already exist locally, and `image_id` must come from that exact
installed image. The harness verifies it before creation and runs Compose with
`--pull never`; it cannot contact a registry during the approved proof.

The approval may be committed in a later approval-record commit. In that case,
check out the approved source candidate in a clean worktree and pass the
approval record's absolute path. The candidate worktree itself must remain at
the exact approved SHA.

## Approved execution command

Only after the exact G1-D record exists:

```powershell
npm run test:db:upgrade -- --approval-file <absolute-path-to-approval.json>
```

Do not start, restart, or tear down the service manually. The single runner:

1. validates approval, clean HEAD, migration hashes, Docker endpoint, Compose
   bytes, and absence of stale named resources before creation;
2. creates the isolated service and named volume;
3. uses Drizzle's repository migrator with a generated byte-identical view
   ending at `0017`;
4. inserts only unmistakably synthetic predecessor rows;
5. applies the unmodified full folder so Drizzle applies `0018` once;
6. verifies preserved counts/relationships, catalog objects, and the
   `agentoma_app` `INSERT`/`SELECT`-only table grants;
7. restarts the same container, proves the head/count/catalog snapshot survived;
8. verifies ownership, destroys the exact container/network/volume in `finally`;
9. writes one non-overwriting, payload-free evidence record under the candidate
   SHA.

No argument or invalid approval fails with a safe reason before any Docker
command. Runtime execution remains **NOT RUN** until a new G1-D is granted.
